# 98 分层架构与变更规范（pokedunk-v2）

> 工作约定。任何改动：先判层 → 再实施 → 后验证 → 必文档。
> **v2 基线（2026-11-07，随 GDD v2.3）**：本项目**全部代码可读可维护**——不存在 minified 打包产物。play 包（旧项目压缩引擎）是**翻译参照物**，不进入运行时。

## 四层定义

| 层 | 名称 | 范围 | 目录 | 原则 |
| --- | --- | --- | --- | --- |
| **L1** | UI 与交互 | 视觉、文案、布局、输入映射、动画、提示、音画表现 | `css/`、`js/ui/` | 只管"看起来/听起来/操作起来"如何，**不蕴含玩法规则** |
| **L2a** | 系统层 | 经济/商店/孵蛋/树果/结缘/仓库/图鉴/旅程状态机/存档 | `js/systems/`、`js/journey/` | 只管"规则与数据"，不硬编码表现 |
| **L2b** | 引擎层 | 比赛引擎+数值机器（翻译自 play 包） | `engine/` | **行为等价铁律**：数值公式/概率/手感参数与原版逐行一致，由 seed 对照测试保证；调平衡必须走 GDD 变更流程，禁止在引擎文件里夹带改动 |
| **L3** | 文档说明 | GDD + docs/ 全部文档 | `docs/` | **穿透层**：同时描述并约束 L1/L2，任何一层的改动必须落到对应文档 |

## 独立性规则

1. **层间单向依赖**：`L1 → L2a → L2b`。引擎层不知道 UI 和系统的存在（通过参数/事件通信）；系统层不直接操作 DOM；UI 层不写玩法规则。
2. **交接面明确定义**：
   - 存档：唯一持久键 `pokedunk.save.v1`（localStorage，单档自动），云同步走平台 sync
   - 引擎输入：配置对象（两队 roster+boost、难度、seed、quarterLen）
   - 引擎输出：事件流（比分/得分者/受伤/进化/结算）
   - 平台 API：`window.LampsGame` / `window.LampsPlatform`
3. **一切改动 = 直接编辑对应源文件**。不存在"锚点手术/打包代码触碰"概念（旧项目专用，本项目作废）。
4. **发布缓存纪律**：每次修改 JS/CSS 后，递增 index.html 中全部引用的 `?v=N`。

## 引擎翻译验收（进入系统层开发的前置门槛）

1. prettier 格式化 play 包为工作底稿
2. 按 GDD S12 对照表逐项翻译至 `engine/`
3. **seed 对照测试**：同一 seed + 同一配置 → 新旧实现比分/事件流/统计逐帧一致；全部通过才算翻译完成
4. 翻译期间任何数值"顺手调整"视为违规

## 变更流程（每次改动必走）

1. **判层**：改动属于 L1 / L2a / L2b / 跨层；跨层的拆成两步分别实施。
2. **实施**：直接编辑对应源文件；改 L2b 必须先跑 seed 对照测试。
3. **验证**：语法校验 + 浏览器回归（控制台 0 错误）+ 涉及功能点测。
4. **文档同步**：更新 GDD/docs 受影响小节 + 在下方变更日志登记一行。
