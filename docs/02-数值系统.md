# 02 数值系统（L2 · 数值与公式）

> 球员面板怎么算出来的，命中率受什么影响。

## 球员数据结构

每只球员：`[图鉴号, 名字, [属性], 位置, spd, sht, ins, pas, def, blk, reb, hnd]`

八维属性：速度 spd、投篮 sht、终结 ins、传球 pas、防守 def、盖帽 blk、篮板 reb、控球 hnd。
另有体力 STA（动态值，非面板）。

## OVR（综合评分）

- 按位置加权：如 PG = spd/sht/pas/hnd 各 0.2 + def/ins 各 0.1。
- 公式：`clamp((加权和 - 60) × 1.25 + 58, 25, 99)`。
- 体型由种族身高体重对数映射，影响干扰与冲撞。

## 命中率相关数值

| 项 | 数值 |
| --- | --- |
| perfect 命中率 | 2 分 .94 / 3 分 .86 |
| 火热手感加成 | 命中 +0.25，完美窗口 ×1.7，扣篮距离 +4 |
| 抢断基础概率 | `0.1 + (def - hnd) / 220` |
| 冲撞得手概率 | 基础 × 克制倍率（0×→0，≥2×→1.5，<1×→0.6），含体型差与 def-hnd |

## 体力模型

- 消耗/秒：`0.0044 × (1.6 - stamina/100) + 加速时 0.0022`，按 `120/节长` 缩放。
- effort < 0.55 后效率降至 0.82~1。
- 节间回复，Q3 额外 +0.3。
- 体力 < 0.5 触发自动换人（可关）。

| 档位 | CPU 加成 cpuBoost | 完美窗口 green | AI 侵略性 aggro | AI 反应 react | CPU 投篮 cpuShot | 干扰 contest | 移动辅助 assist | 橡皮筋 catchup |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 新秀 rookie | -14 | ×1.9 | 0.3 | 0.5 | -0.1 | 0.5 | ✓ | 1 |
| 职业 pro | -5 | ×1.35 | 0.6 | 0.3 | -0.04 | 0.8 | ✓ | 0.5 |
| 全明星 allstar | 0 | ×1.1 | 0.9 | 0.2 | 0 | 0.9 | ✗ | 0 |
| 传说 legend | +4 | ×0.85 | 1.15 | 0.12 | +0.03 | 1.0(推测) | ✗ | 0 |

- 难度=**外部参数**：`Dt` 构造器吃 `cfg.difficulty`，映射到 `Zt` 数据表——调难度/强度=改配置或数据，**引擎代码零改动**
- 每队另有独立 `boost` 字段（队对象传入）：道馆 −3~+3、四天王 +4 即由此注入，与难度档叠加
- 追分（catchup）：落后方获得隐性命中率补偿，数值=落后差距 × 档位系数

## 必杀系统（special，完整版）

**槽位**：每名球员一个充能槽 0→1，满后由操控者按键释放（键盘 I/E，触屏必杀键），AI 也会按条件自动释放（quake 仅近距离 <6~9 尺、freeze 落后/对手快攻时、其余在出现空位或对手快攻时）。

**充能来源（全部被动，比赛行为积累）**：

| 行为 | 充能 |
| --- | --- |
| 盖帽 | +0.35 |
| 抢断 | +0.30 |
| 得分 | +0.30 |
| 助攻（4 秒内传给得分者） | +0.12（传球者得） |
| 篮板 | +0.10 |

**必杀效果（按精灵主属性自动决定，Wa 表，共六类）**：

| 效果 | 属性 | 描述（Ps 表原文意译） |
| --- | --- | --- |
| Surge 急冲 | 电/一般/飞行 | 5 秒无限加速 + 移速 +25% |
| Lock-In 锁定 | 超能力/仙/钢 | 下一次投篮必定完美出手 |
| Phase 相位 | 幽灵/恶/毒 | 5 秒不可被抢断/推搡/盖帽 |
| Blaze 燃烧 | 火 | 立即进入火热手感 |
| Quake 震地 | 地面/岩石/格斗/水 | 击倒 14 尺内全部对手，属性克制倍率生效 |
| Freeze 冰冻 | 冰/草/虫 | 对方全队减速 5 秒 |

**要点**：
- `special` 是槽（充能系统）；招式名（VOLT TACKLE/CALM MIND 等）只是六类效果的皮肤，精灵卡 `special` 字段=按主属性映射的**效果类别**
- 必杀释放不受属性克制影响（quake 的击倒例外，克制生效）
- 双方 AI 与玩家同一套规则；practice 模式 AI 不主动放
- 训练师之旅沿用零改动；"属性羁绊"若做队伍级必杀加成，接口就在这里

# 附：构筑系统数值增补（v2.4 · 2026-11-11 定稿）

> 本节为 2026-11-11 用户定稿的构筑系统地基，优先级高于本文旧段落中与之冲突的描述。
> 范围：训练师之旅（journey）。快速比赛不接入稀有度/训练/道具/羁绊/位置适配，保持原版行为。

## A. 三层数值模型

| 层 | 名称 | 内容 | 是否随存档 | 说明 |
| --- | --- | --- | --- | --- |
| L1 | 种族值 | `getPokemon(dex).r` 八维、体型、属性、推荐位置 | 静态数据 | 稀有度的主要载体 |
| L2 | 成长值 | 等级 `bonus` + 训练 `train` + 道具 `item` | 存档 | 单项封顶 99 |
| L3 | 有效值 | 场内实际生效值 | 运行时 | 位置修正 + 羁绊 + 引擎克制/体力 |

### A1. 成长值预算

| 来源 | 上限 | 规则 |
| --- | --- | --- |
| 等级 | 196 | 每级随机 +2，沿用 `rollGrowth` |
| 训练 | 40 | 且 ≤ 等级 ÷ 2；无每周购买上限 |
| 道具 | 20 | 每种道具最多 4 次 |
| 合计 | 256 | 上限，不是保底；单项 99 封顶 |

- `bonus` 只存等级成长，不混入训练/道具（便于审计和重置）。
- `train.stats`、`item.stats` 与 `bonus` 相加后再单项封顶 99。
- 训练价格动态上涨：`20 + 5 × 该精灵已训练点数`；无每周限制，重置返还 80% 训练点，不退币。
- 道具来源：成就/赛季/活动，商店每周限 1；不做无限购买。
- 256 是总预算上限，不代表每只都能八维 99：普通档受基础值限制，通常只能把 3~4 项练到 99；传说档基础高，约 72 点即可八维全满。

### A2. 存档字段

```js
mon = {
  dex, level, xp, bonus,        // 现有字段；bonus = 等级成长
  train: { points: 0, stats: { spd:0, sht:0, ins:0, pas:0, def:0, blk:0, reb:0, hnd:0 } },
  item:  { points: 0, stats: { ... }, used: {} }, // used: itemId -> count
  pos,                          // 推荐位置（数据值，进化时更新）
}

save.assign = { [monId]: "PG" | "SG" | "SF" | "PF" | "C" } // 实际位置；缺省 = 推荐位置
```

- 旧档迁移：`train`/`item` 缺失时补零；`assign` 缺失时按 `mon.pos` 初始化。
- `mons.pos` 继续表示推荐位置，不存实际位置。

### A3. 计算管线（唯一入口）

```js
growthStats(mon) = base.r
  + mon.bonus
  + mon.train.stats
  + mon.item.stats
  // 每项 clamp 0..99

effectiveStats(mon, assignedPos) = growthStats(mon) × posMult(mon, assignedPos)
  // 羁绊在此之后叠加，再 clamp 0..99

mainOVR(mon)      = calcOVR(mon.pos, growthStats(mon))
posOVR(mon, pos)  = calcOVR(pos, growthStats(mon))
versatility(mon)  = round(avg(posOVR(mon, p) for p in POSITIONS))
monPower(mon, assignedPos) = calcOVR(assignedPos, effectiveStats(mon, assignedPos) 含羁绊)
teamPower(save)   = avg(top5 monPower of team)   // 防藏强
```

- 所有页面、商店定价、匹配、排行榜必须只走 `monPower` / `mainOVR` / `versatility`；禁止再直接用 `getPokemon(dex).ovr` 作为“当前战力”。
- 商店定价使用**种族 OVR**（新精灵未养成），不使用当前养成值。
- `calcOVR` 仍按旧公式和 25~99 封顶；不改引擎。
- 自然位置且无训练/道具/羁绊时，`monPower === buildPlayer(dex, bonus).ovr`，保证旧行为与 seed 对照不变。

## B. 稀有度：A+ 全能度

### B1. 三档

| 档位 | 判定 | 单项上限 | 定位 | 获取 |
| --- | --- | --- | --- | --- |
| 普通 | 基础 OVR < 70 | 99 | 专精：主位置 3~4 项 99，换位置弱 | 商店/蛋常见 |
| 稀有 | 基础 OVR 70~84 | 99 | 多面：6~8 项 99，可打 2~3 个位置 | 商店少量/蛋稀有/战胜签约 |
| 传说 | 传说/幻之白名单 | 99 | 全能 + 早熟：八维 99，五位置都能打 | 不进每日商店；蛋 1% 独立概率；联赛冠军/四天王共享赛季 2 选 1 |

- 传说档用 dex 白名单，不用“OVR ≥ 85”自动判定，避免把强力非传说误标。
- 稀有度不是属性倍率；差异来自：基础值、成长效率、全能度、获取难度。
- 商店：传说 dex 不进入货架；蛋池：传说 1% 独立判定，其余普通/稀有按权重抽取。
- 同种唯一仍然生效；传说全档案一只。

### B2. 展示

- 队伍卡/详情页：`主位置 OVR / 全能度`。
- 普通：主位置 99 / 全能 75；传说：主位置 99 / 全能 95。
- 主位置 = 推荐位置（`mon.pos`）；全能度 = 五位置 OVR 平均。
- 超梦：传说档，高基础、约 Lv40 八维全满，定位 = 毕业奖励/快速比赛神器/图鉴荣誉，不是常规养成核心。

### B3. 边界

- 所有人单项 99 封顶；不做稀有度硬上限。
- 普通精灵可以主位置 99，但全能度低；换位置按 C 节扣。
- 传说不能通过每日商店获得；获取入口 = 蛋 1% / 四天王首通自选 / 战胜签约。

## C. 位置：推荐位置 + 适配度

### C1. 定义

- `pos` = 推荐位置（数据字段），用于图鉴/商店/AI/默认首发。
- `fit(pos)` = 位置适配度：

```text
fit(pos) = Σ(成长值[i] × POSITION_WEIGHTS[pos][i]) / 99
```

- `POSITION_WEIGHTS` 沿用 `engine/data/positions.js`，不另调。
- `mainPos = mon.pos`（推荐）；`bestPos = argmax fit`。
- 若 `fit(bestPos) - fit(mainPos) < 0.05`，显示“推荐 X · 副 Y”，不视为矛盾。
- 若差距 ≥ 0.05，视为数据异常，记入审计日志（正常不应出现）。

### C2. 数据审计结论（2026-11-11）

对 291 条跑 `POSITION_WEIGHTS` 适配度：

| 情况 | 数量 | 占比 |
| --- | --- | --- |
| 最优位置 = 推荐位置 | 176 | 60.5% |
| 差距 < 0.02（邻位） | 91 | 31.3% |
| 差距 0.02~0.035（邻位） | 24 | 8.2% |
| 差距 ≥ 0.05 | 0 | 0% |

- 最大差距 0.035；全部为 PF↔C、SF↔SG、SF↔PG 等相邻位置。
- 结论：原版数据可信；不存在真正的“推荐位置 vs 八维位置”矛盾，只有双位置倾向。

### C3. 越位倍率

```text
recFit = fit(mon.pos)
if assignedPos == mon.pos: posMult = 1.0
else: posMult = clamp(0.90 + 0.10 × fit(assignedPos) / recFit, 0.90, 1.0)
```

- 推荐位置：100%。
- 邻位（PF 打 C）：通常 97%~100%。
- 明显越位（C 打 PG）：最低 90%。
- `recFit == 0` 时按 0.90 处理，避免除零。
- 位置倍率只作用于比赛有效值，不改变 `growthStats` / 存档。

### C4. 自动排阵

- 从队伍 10 人中穷举 5 人 × 5 位置（最多 30,240 种），选：
  1. 总 `monPower` 最高；
  2. 同分时，五位置覆盖优先；
  3. 再同分时，全能度高者优先。
- 玩家可手动改 `assign`；开赛前锁定。

### C5. 五位置齐羁绊

- 条件：首发 5 人实际位置覆盖 PG/SG/SF/PF/C 各 1，且每人：

```text
fit(assignedPos) / fit(mon.pos) ≥ 0.90
```

- 5 个 C 硬贴 5 个位置标签不算达成。
- 传说八维平均，五个位置 fit 接近，天然满足“全能”优势。

### C6. 进化与快速比赛

- 进化：`mons.pos` 更新为新形态推荐位置；`assign` 保留，按新八维重算 fit；不做“位置熟练度”，所以无投资损失。
- 快速比赛：`assignedPos = mon.pos`，`posMult = 1.0`，不接入训练/道具/羁绊；保持原版行为。
