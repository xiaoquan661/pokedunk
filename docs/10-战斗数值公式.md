# 10 · 战斗内数值影响公式

> 目的：单独记录“八维数值 → 比赛内实际行为”的全部现行公式，供调参、平衡讨论和回归测试使用。
> 代码来源：`engine/readable/play-core.js`（函数名标注在每节标题后）。
> 约束：本文记录的是**当前已上线公式**，调整任何系数前先改本文，再改代码。

## 0. 数值进入比赛前的口径

### 0.1 八维来源

```
最终八维 = clamp(种族值 + 等级成长 + 训练点 + 道具点, 1, 99)
```

- 训练：每点 +1；免费点/返还点优先，购买点按价格扣币。
- 道具：每种最多使用 4 次，每次 +1 指定属性，单项 99 封顶。
- 对局开始时会再叠加一次全队加成（位置齐 +2 / 难度 CPU boost），运行时 clamp 到 20–99。

### 0.2 OVR（`calcOVR`）

```
OVR = clamp(round((Σ 属性 × 位置权重 − 60) × 1.25 + 58), 25, 99)
```

位置权重：

| 位置 | 权重 |
| --- | --- |
| PG | spd .20 / sht .20 / pas .20 / hnd .20 / def .10 / ins .10 |
| SG | sht .30 / spd .15 / hnd .15 / ins .15 / def .15 / pas .10 |
| SF | sht .20 / ins .20 / def .20 / spd .15 / reb .10 / blk .10 / pas .05 |
| PF | ins .25 / reb .20 / blk .15 / def .15 / sht .10 / spd .10 / pas .05 |
| C | ins .20 / reb .25 / blk .25 / def .10 / pas .10 / sht .05 / spd .05 |

### 0.3 体力系数（`effort`）

```
energy ≥ 0.60 → effort = 1
energy < 0.60 → effort = 0.80 + 0.20 × (energy / 0.60)
```

最低 0.80，即体力耗尽时所有受 effort 影响的行为只有满体力的 80%（S39：阈值 0.55→0.60，最低 0.82→0.80）。

## 1. 移动速度（`updatePlayer`）

```
基础速度 = (9 + spd × 0.105) × effort
冲刺      × (1.30 + spd × 0.0025)（spd 40→1.40，99→1.5475）
必杀加速  × 1.20
减速状态  × 0.55
持球      × (0.74 + hnd × 0.002)（hnd 40 → 0.82，hnd 99 → 0.938）
抢断动作  × 0.50
```

**参考值**

| spd | 基础速度 |
| --- | --- |
| 40 | 13.2 |
| 50 | 14.25 |
| 70 | 16.35 |
| 90 | 18.45 |
| 99 | 19.40 |

- 满速约为 50 速度的 1.36 倍；S40 把低速度的下限压低，速度差比旧表更明显。

## 2. 体力与耐力（`ln` / `tickStamina`）

```
耐力 = clamp(round(32 + reb × 0.55 + def × 0.20), 40, 99)
每秒消耗 = [0.0044 × (1.6 − 耐力/100) + (冲刺中 ? 0.0016 + (100 − 耐力)/100 × 0.0026 : 0)] × (120 / 节长)
冲刺条恢复速度 = 0.10 + 耐力/100 × 0.12 /秒
```

- 耐力越高，体力下降越慢，且冲刺额外消耗更低；S39 后耐力 62 与 99 的冲刺可持续时间约差 1.6 倍。
- 体力低于 60% 后通过 `effort` 影响速度、投篮、上篮、扣篮（最低 80%）。
- 替补席每秒恢复 0.005（受比赛时钟缩放）。

## 3. 投篮（`baseProb` / `releaseShot` / `contest` / `greenWindow`）

### 3.1 基础命中率

```
近距离（<8）     = 0.55 + ins × 0.004
中距离（8–24）   = clamp(0.20 + sht × 0.0042 − (距离 − 8) × 0.007, 0.10, 0.75)
远距离（>24）    = clamp(0.10 + sht × 0.0037 − (距离 − 24) × 0.03, 0.02, 0.60)
```

### 3.2 按键评价

绿窗（`greenWindow`）：

```
绿窗 = (0.012 + sht/100 × 0.055) × 难度系数 × (火热 ? 1.7 : 1)

人类玩家的难度系数 = diff.green × (1 + 0.3 × catchup)
CPU 的难度系数 = 1
```

低投篮的绿窗更窄，高投篮基本维持原宽度；投篮键的完美白闪/震感只在 **sht ≥ 90** 时触发，低投篮玩家需要自己盯蓄力条判断释放点。

评价判定：

| 误差范围 | 评价 |
| --- | --- |
| ≤ 绿窗 | perfect |
| ≤ 绿窗 × 2.3 | good |
| ≤ 绿窗 × 4.5 | early / late |
| 更大 | very-early / very-late |

### 3.3 最终命中率（`releaseShot`）

```
perfect   = clamp((三分线外 ? 0.54 : 0.62) + (sht − 40) × 0.0059, 0.50, 0.97) − (1 − 干扰系数) × 0.55
good      = 基础命中 × 干扰系数 + 0.06
early/late= 基础命中 × 干扰系数 × 0.80
very-*    = 基础命中 × 干扰系数 × 0.30
```

修正：

```
× (0.7 + 0.3 × effort)
火热状态 +0.25
距离 > 35：perfect 最多 0.25，其余最多 0.04
```

### 3.4 干扰（`contest`）

对 7 英尺内每名防守者：

```
单人干扰 = (1 − 距离/7) × (0.25 + def × 0.0025 + 体型 × 0.07)
防守者正在起跳（z > 0.8）：× 1.4
防守者在投篮者身后/侧后：× 0.6
干扰 = 所有防守者的最大值
干扰系数 = clamp(1 − 干扰, 0.35, 1)
```

人类玩家再乘难度系数 `diff.contest`。

## 4. 上篮（`releaseLayup`）

```
命中 = (0.55 + ins × 0.004) × (0.45 + 0.55 × 干扰系数) × (0.7 + 0.3 × effort)
火热 +0.20
```

## 5. 扣篮（`startDunk` / `dunkRange`）

```
命中 = clamp(0.50 + ins × 0.0035 − (1 − 干扰系数) × 0.6, 0.30, 0.93) × (0.7 + 0.3 × effort)
火热 / 锁定 = 0.99
扣篮范围 = 3 + ins × 0.09（火热再 +4）
```

| ins | 扣篮范围 |
| --- | --- |
| 50 | 7.5 |
| 70 | 9.3 |
| 90 | 11.1 |

## 6. 盖帽（`updateDunk` / `updateShot`）

### 6.1 跳投篮 / 上篮

```
盖帽率 = clamp(0.15 + blk × 0.004 − 投篮者 sht × 0.002 − (跳投 ? 0.05 : 0), 0.05, 0.60)
```

### 6.2 扣篮

```
盖帽率 = clamp(0.25 + blk × 0.004 − 扣篮者 ins × 0.0025 + (体型差) × 0.3, 0.08, 0.55)
```

### 6.3 起跳高度

```
垂直初速 = 14 + max(blk, reb) × 0.05
```

## 7. 抢断（`trySteal` / `updatePass`）

### 7.1 持球抢断

```
成功率 = clamp(0.10 + (抢断者 def − 持球者 hnd) / 220, 0.03, 0.38)
对方处于投篮 / 上篮动作 × 0.4
必杀相位 = 0
```

- 常规抢断距离 4.6；冲刺/怒气状态下推撞判定距离 4.8。
- 抢断冷却 0.6 秒。

### 7.2 传球拦截

```
拦截率 = clamp(0.08 + (拦截者 def − 传球者 pas) / 200 + (人类按下抢断 ? 0.20 : 0), 0.03, 0.40)
空中接力且拦截者未起跳 × 0.2
```

## 8. 卡位 / 推撞（`trySteal` 推撞分支）

```
成功率 = clamp(0.55 + (体型差) × 0.8 + (def − 对方 hnd) / 250, 0, 0.95)
属性克制：克制 ×1.5 / 被克 ×0.6 / 无效 ×0
```

- 推撞成功后对方进入 1.1 秒硬直。

## 9. 篮板（`loosePickup`）

```
抢板评分 = reb + 随机(0, 24) + (起跳高度 > 0.5 ? 10 : 0)
评分最高者拿球
```

- 35 点随机浮动会明显压缩高篮板与低篮板的差距。

## 10. 传球（`attemptPass`）

```
传球速度 = 40 + pas × 0.24
空中接力 = 32（固定速度）
```

## 11. AI 防守反应（`reactTime`）

```
反应时间 = 基础值 + (100 − def)/100 × 0.25 + 随机(0, 0.08)
```

| def | 额外反应时间 |
| --- | --- |
| 40 | 0.150 秒 |
| 70 | 0.075 秒 |
| 99 | 0.0025 秒 |

## 12. 属性克制（`Va` / 推撞）

- 只影响推撞成功率与地震/冰冻类必杀的击退与减速；
- 不影响投篮基础命中；
- 推撞倍率：克制 ×1.5、被克 ×0.6、无效 ×0。

## 14. 已知的“差异被吃掉”位置

1. **移动速度**：spd 40 → 99 只有 14.40 → 19.41（1.35 倍）；基础值 11 占比过高。
2. **绿窗**：sht 40 → 99 从 34.0ms 增至 66.4ms（约 1.95 倍）；低投篮窗口明显更窄，且完美白闪/震感只有 sht ≥ 90 才有。
3. **篮板**：随机已从 35 降到 24；10 点篮板优势约 83% 抢到，20 点约 98.6%。
4. **抢断**：成功率有 0.03–0.38 硬上下限；def 99 对 hnd 40 已摸到上限 36.8%，再堆无收益。
5. **盖帽 / 干扰**：同样有硬上下限（盖帽 5%–60%，干扰系数 35%–100%），满值后继续堆属性收益归零。
6. **投篮**：完美评价改为从 40 投篮起算、每点 +0.59%；40 → 99 的完美出手差距约 35 个百分点（2 分 62.0% → 96.8%，3 分 54.0% → 88.8%）。
7. **体力 / 冲刺**：耐力池 62 → 99；冲刺额外消耗随耐力降低而升高；冲刺速度从固定 ×1.42 改为 `1.30 + spd×0.0025`，高速度的冲刺收益更高。

## 16. 战斗数值的干预层（改平衡时必须一起看）

比赛里的最终数值不是只由 `play-core.js` 决定。下面这些层会在不同阶段改写属性或公式，调平衡时先判断改哪一层。

| 层 | 文件 / 函数 | 干预内容 | 何时生效 |
| --- | --- | --- | --- |
| 局外成长 | `js/systems/build.js` `growthStats` | 种族值 + 等级成长 + 训练点 + 道具点，最后 clamp 1–99 | 进场前 |
| 位置适配 | `build.js` `posMult` | 按位置给八维乘系数 | 进场前 |
| 羁绊 | `build.js` `bondMultipliers` | 最多 3 条羁绊，按属性乘 / 加 | 进场前 |
| 阵容完整 | `play-core.js` `Ot` | 首发覆盖 5 个不同位置 → **全属性 +2** | 进场时 |
| 对手校准 | `js/journey/gyms.js` `GYM_BONUS` + 赛季 `extra` | 八维统一 -7 ~ +3；第 2 赛季起每季再 +2 | 组建对手时 |
| 野球等级 | `js/journey/wild.js` `levelBonus` | 八维统一 `round((等级−5)×0.6)` | 野球进场前 |
| 每日修正 | `js/journey/daily.js` `DAILY_MODS` / `buildOpponent` | 双方八维 +3 ~ +8；对手按目标 OVR 补 0 ~ 25 点 | 每日挑战进场前 |
| 引擎队伍 boost | `play-core.js` `Es` | `全属性 += Ot + cfg.boost + 难度 cpuBoost`，clamp 20–99 | 建球员时 |
| 难度档 | `play-core.js` `DIFFICULTY_LEVELS` | 绿窗、干扰、AI 反应、AI 进攻欲望、CPU 投篮修正、追分强度 | 比赛内 |
| 追分橡皮筋 | `play-core.js` `catchup` | 玩家落后 6 分以上时，绿窗最多 +30%，CPU 进攻欲望最多 -50% | 比赛内 |
| 必杀效果 | `play-core.js` `useSpecial` / `SPECIAL_EFFECTS` | 爆发、锁定、相位、火热、震击、冰冻六类 | 比赛内 |
| 一键模拟 | `js/journey/match-screen.js` `makeSimCfg` / `capSimMargin` | 无头模拟额外加 CPU boost（rookie -14 / pro -5 / allstar 0 / legend +4），分差封顶 30 | 模拟时 |
| 赛制 | 各模式的 `quarterLen` / `quarters` | 联赛 180×4、快速 120×2、野球 60×2 半场、教学 90 且无体力 | 进场时 |

**关键提醒**：

1. `boost` 不是“只加 OVR”，而是**八维同时加减**；+2 的实际强度远大于面板上 2 点。
2. 阵容位置齐全自带全属性 +2，和羁绊、训练点是乘算/加算叠在一起的。
3. 每日挑战 modifier 对双方同时生效，所以它拉不开双方差距，只改变当天的手感。
4. 一键模拟不是独立模型，仍是同一个 `MatchEngine`，但额外补 CPU boost 且比分封顶；模拟结果不能直接当真人比赛的强度依据。
5. 赛季其他球队的积分榜模拟是另一套球队评分模型（`zs`），不参与你手动打的这场。
